Master Frontend + App Engineering Path

One language.
Web, mobile, SaaS — mapped.

JavaScript is the one root. TypeScript, React, Next.js, and React Native all grow out of it — so this map treats them as one continuous tree, not four separate roadmaps. Includes the SaaS-specific layer most tutorials skip: billing UI, multi-tenancy, analytics, and shipping to both the browser and the app store.

Tier 00 — Web Foundations
0x00
Core Web Fundamentals

Every framework below is an abstraction over these three — skip them and React's rules stop making sense the moment something breaks.

HTML5Semantic structure — the tags you choose directly affect accessibility and SEO, not just layout.
CSS3Box model, Flexbox, Grid, specificity. Every "why isn't this centered" bug traces back here.
Modern JavaScript (ES6+)Closures, promises/async-await, destructuring, modules. This is the language every tool on this page compiles down to.
Browser Rendering & DOM AddedParse → Style → Layout → Paint → Composite. Explains why some CSS changes are expensive and why React batches updates.
Tier 01 — Language Mastery
0x01
TypeScript Mastery

You called this out specifically — and it's the right call. Next.js, most component libraries, and every serious SaaS codebase assume TypeScript, not plain JS.

Types & InterfacesModel your data shapes so mismatches get caught at compile time, not in a user's browser.
GenericsWrite reusable functions/components that stay type-safe across different data shapes — the core of typing a good API client.
Utility TypesPartial, Pick, Omit, Record — transform existing types instead of redefining them.
Strict tsconfigTurn on strict: true from day one — retrofitting strictness onto a loose codebase later is painful.
Tier 02 — Core Framework
0x02
React

The mental model every other tool in this map — Next.js, React Native, most state and data libraries — is built directly on top of.

HooksuseState, useEffect, useMemo, useCallback, custom hooks — the entire modern React API surface.
Component ModelProps down, events up, composition over inheritance — the design philosophy behind every well-structured React app.
Context APIShare state across a component tree without prop-drilling it through ten layers.
Reconciliation & Virtual DOMWhy React re-renders what it does, and why keys matter in lists — understand this before you fight a "why is this not updating" bug.
0x03
Next.js

The production default for React-based SaaS — solves routing, rendering strategy, and API endpoints in one framework instead of assembling them yourself.

App RouterFile-system based routing with layouts, nested routes, and loading/error states built in.
SSR / SSG / ISR / CSRChoose per-page how a page is rendered — server, static, incrementally revalidated, or client — based on how fresh the data needs to be.
Server ComponentsRender components on the server with zero client-side JS shipped for them — big wins for initial load time on content-heavy SaaS pages.
API Routes & MiddlewareShip a lightweight backend endpoint or request interceptor (auth checks, redirects) from inside the same project.
Tier 03 — State & Data
0x04
State Management

"Where does this piece of data live" is one of the most consequential architecture decisions in a growing SaaS frontend.

Redux ToolkitPredictable, centralized state with dev tools and time-travel debugging — still the right call for large, complex apps.
ZustandMinimal, hook-based global state without Redux's boilerplate — the modern default for most mid-size apps.
JotaiAtomic state model — good fit when state is naturally split into many small, independent pieces.
0x05
Data Fetching & Server State

Server data isn't like client state — it goes stale, needs caching, and can fail mid-flight. These tools handle that so you don't hand-roll it badly.

TanStack QueryCaching, background refetching, and request deduplication for server data — the standard companion to any REST or GraphQL API.
SWRVercel's lighter-weight data fetching hook — "stale-while-revalidate" caching with a smaller API surface.
tRPCEnd-to-end typed API calls between a TypeScript frontend and backend — no manual API client or schema duplication.
0x06
Forms & Validation

Every SaaS product is mostly forms — signup, settings, billing, onboarding. Getting this layer right removes a huge class of bugs and support tickets.

React Hook FormUncontrolled-by-default forms for performance — minimal re-renders even on large, complex forms.
ZodSchema validation that also gives you inferred TypeScript types — one schema, validated on both client and server.
FormikOlder but still common alternative — know it for legacy codebases even if you reach for RHF on new work.
Tier 04 — UI & Styling
0x07
Styling Systems

Determines how fast your team can build UI and how consistent it stays as more people touch the codebase.

Tailwind CSSUtility-first classes directly in markup — currently the default choice for fast-moving SaaS teams.
CSS ModulesLocally scoped class names with zero runtime cost — a solid plain-CSS option inside component-based frameworks.
styled-components / EmotionCSS-in-JS — colocate styles with components, with dynamic theming based on props.
0x08
Component Libraries & Design Systems

Don't hand-build a date picker from scratch — the accessibility edge cases alone will eat a week you don't have.

shadcn/uiCopy-paste, fully-owned components built on Radix — currently the most popular choice for new SaaS UIs.
Radix UIUnstyled, accessible primitives (dialogs, dropdowns, popovers) that handle keyboard nav and ARIA for you.
StorybookBuild and visually test components in isolation — doubles as living documentation for your design system.
Gap filled — Atomic Design: organize components as atoms → molecules → organisms → templates → pages. Gives a shared vocabulary for "how big should this component be" as the library grows.
Tier 05 — Quality & Performance
0x09
Testing

Lets you ship UI changes fast without manually clicking through every screen after every commit.

Vitest / JestUnit and integration test runners — Vitest is the faster, Vite-native pick for new projects.
React Testing LibraryTests components the way a user interacts with them, not their internal implementation details.
PlaywrightFast, reliable end-to-end browser testing across Chromium, Firefox, and WebKit.
CypressDeveloper-friendly E2E testing with a strong visual debugging experience — the other major E2E option.
0x0A
Performance & Web Vitals Added tier

A slow SaaS dashboard directly costs you trial conversions and retention — this isn't optional polish, it's a growth lever.

Code Splitting & Lazy LoadingShip only the JS a page actually needs — dynamic() imports and route-based splitting in Next.js.
MemoizationuseMemo, useCallback, React.memo — prevent expensive re-renders, but only after profiling shows they matter.
Image OptimizationNext.js <Image> — automatic resizing, lazy loading, and modern formats (WebP/AVIF) without manual work.
Core Web VitalsLCP, INP, CLS — the metrics Google actually uses to rank and that real users actually feel.
LighthouseAutomated auditing for performance, accessibility, and SEO — run it in CI so regressions get caught before merge.
0x0B
Accessibility (a11y) Added tier

Legally required in many markets for SaaS products, and simply excludes real paying customers when skipped.

WCAG GuidelinesThe standard your product likely needs to meet — color contrast, focus order, alt text as baseline requirements.
ARIAFill gaps native HTML can't express — but the first rule is: use semantic HTML before reaching for ARIA at all.
axe / Lighthouse a11y auditAutomated scanning to catch the easy 30–40% of accessibility issues before manual review.
Tier 06 — Build & Tooling
0x0C
Build Tools & Code Quality

The invisible layer that turns your source code into what actually ships — and keeps a team's code style from fragmenting.

ViteNear-instant dev server startup and HMR — the modern default bundler for non-Next.js React apps.
TurbopackNext.js's Rust-based bundler, built for large app build/dev speed as projects scale.
WebpackThe older, still-widespread bundler — worth understanding since much tooling still documents against it.
ESLint & PrettierCatch bugs and enforce a single formatting style automatically, before a PR review ever gets to style nitpicks.
Gap filled — Git Hooks: Husky + lint-staged. Run linting/formatting/tests automatically on commit so broken code never even reaches a PR.
Tier 07 — Auth, Security & Real-Time
0x0D
Authentication (Frontend)

Every SaaS product starts at a login screen — get session handling wrong here and nothing else matters.

Auth.js (NextAuth)Drop-in auth for Next.js — social login, credentials, and session management with minimal setup.
ClerkFully managed auth with prebuilt UI components — fastest path to production-grade auth for a SaaS MVP.
Supabase AuthAuth bundled with a Postgres backend — a good fit if you're already using Supabase for data.
0x0E
Frontend Security Added tier

The browser is a hostile environment by default — assume anything you send to the client can be read or tampered with.

Content Security Policy (CSP)Restricts which scripts/origins can execute on your page — a strong second line of defense against XSS.
Client-side XSS PreventionReact escapes output by default — the risk shows up the moment you use dangerouslySetInnerHTML carelessly.
Secure Token StoragehttpOnly cookies over localStorage for auth tokens — localStorage is readable by any injected script.
CORS AwarenessUnderstand it from the client side too — it explains why a working API call in Postman fails in the browser.
0x0F
Real-Time & Live Data Added tier

Collaborative features, live dashboards, and notifications all need a channel that isn't request/response.

WebSockets / Socket.ioPersistent bidirectional connection for live features — chat, presence, collaborative editing.
Pusher / AblyManaged real-time infrastructure — skip running your own WebSocket servers for most SaaS use cases.
Server-Sent Events (SSE)Simpler one-way server-to-client streaming — a good fit for live notifications or streaming AI responses.
Tier 08 — App Development (React Native)
0x10
React Native Core

Same component model you already know from React — the payoff for mastering React first is that this tier moves fast.

Core ComponentsView, Text, FlatList, Pressable — the native equivalents of HTML elements, rendered to real native views.
React NavigationStack, tab, and drawer navigators — the standard way to structure screens in a mobile app.
Native ModulesBridge to platform-specific APIs (camera, biometrics) when a JS-only library doesn't cover what you need.
0x11
Expo & Build Pipeline

Expo removes almost all of the native build-toolchain pain that used to make React Native setup a multi-day project.

Expo SDKPrebuilt native APIs (camera, notifications, location) without writing native code yourself.
EAS Build / Submit AddedCloud-based builds for iOS/Android and direct submission to the app stores — no local Xcode/Android Studio required.
OTA Updates AddedPush JS bundle updates to installed apps instantly, bypassing the app store review cycle for non-native changes.
0x12
Mobile-Specific Concerns Added tier

The details that don't exist on web at all, and that first-time mobile developers consistently underestimate.

Push NotificationsExpo Notifications or Firebase Cloud Messaging — a core retention lever for any consumer or SaaS mobile app.
Offline StorageAsyncStorage for simple key-value data, MMKV for faster, larger local storage needs.
Deep LinkingOpen a specific in-app screen from a URL, email, or notification tap.
App Store DeploymentApple App Store Connect and Google Play Console review processes — budget real time for this, especially iOS review.
0x13
Cross-Platform Code Sharing Added tier

The real payoff of "everything is JavaScript" — share logic, types, and even UI between your web app and mobile app instead of building both twice.

React Native WebRun React Native components in a browser — one component codebase targeting three platforms.
Expo RouterFile-based routing for React Native, modeled directly on Next.js's App Router — familiar mental model, less to relearn.
Turborepo / NxMonorepo tooling to share types, UI, and business logic between your Next.js web app and React Native app in one repo.
Tier 09 — SaaS Product Layer
0x14
SaaS Essentials Added tier

The layer that turns "a working app" into "a sellable product" — none of this shows up in a typical React tutorial.

Stripe.js / Stripe ElementsEmbeddable, PCI-compliant billing UI — pricing pages, checkout, and subscription management without touching raw card data.
Multi-Tenancy (Frontend)Scope UI, data, and routing per organization/workspace — the structural backbone of any B2B SaaS.
Feature FlagsLaunchDarkly or PostHog flags — ship a feature to specific plans or beta users without a separate deploy.
Internationalization (i18n)next-intl or react-i18next — plan for multiple languages/locales before it's a rushed retrofit.
0x15
Analytics & Product Tracking Added tier

You can't improve activation or retention you aren't measuring — this is standard SaaS instrumentation, not an afterthought.

PostHogProduct analytics, session replay, and feature flags in one open-source tool — popular default for SaaS teams.
MixpanelEvent-based analytics focused on user funnels and retention cohorts.
SegmentSingle tracking layer that fans events out to whichever analytics/marketing tools you plug in — avoids re-instrumenting per tool.
0x16
SEO for SaaS

Your marketing/landing pages live or die on this, even though your logged-in app dashboard doesn't need it at all.

Meta Tags & Open GraphControl how your pages preview when shared on social/Slack — Next.js Metadata API handles this per-route.
Sitemap & robots.txtTell search engines what to crawl and index — auto-generated by Next.js's built-in sitemap support.
Structured Data (JSON-LD)Rich snippets in search results (pricing, reviews, FAQs) that plain meta tags can't produce.
Tier 10 — Deployment & Ops
0x17
Deployment & Hosting

Where the trade-off between "just works" and "full control" gets decided for your project.

VercelBuilt by the Next.js team — zero-config deploys, preview URLs per PR, edge functions out of the box.
NetlifySimilar zero-config hosting, framework-agnostic — a common alternative outside the Next.js ecosystem.
Cloudflare PagesDeploys to Cloudflare's edge network — very fast global response times, generous free tier.
0x18
CI/CD for Frontend

Automates linting, testing, and deployment so shipping a change is a merge, not a manual checklist.

GitHub ActionsRun tests, lint, and type-check on every PR before it's mergeable.
Turborepo Remote CachingSkip re-building/re-testing packages that haven't changed — dramatically speeds up CI in a monorepo.
Preview DeploymentsEvery PR gets its own live URL — reviewers see the actual change running, not just a diff.
0x19
Monitoring & Error Tracking

Frontend errors happen on devices you'll never see — this is how you find out about them before a user emails support.

SentryCaptures errors with full stack traces and the user session context leading up to them.
LogRocketSession replay paired with error tracking — literally watch what the user did right before it broke.
Web Vitals MonitoringTrack real-user performance metrics in production, not just lab conditions from Lighthouse.
Tier 11 — Architecture at Scale
0x1A
Frontend Architecture

Where a strong individual contributor becomes a lead — every tool above is a component; this is judgment about how to arrange them.

MonoreposTurborepo or Nx managing web, mobile, and shared packages together — one source of truth for types and UI.
Micro-FrontendsSplit a large app into independently deployable pieces — a scale-driven decision, not a default one.
Feature-Based Folder StructureOrganize by feature/domain instead of by file type — scales far better than a global components/ folder past a certain size.
Server vs Client Component BoundariesDeciding where the "use client" line goes is now a real architecture decision in Next.js — get it wrong and you ship far more JS than needed.
Gap filled — Design-to-Code Workflow: Figma dev mode and shared design tokens (colors, spacing, type scale) keep design and code from drifting apart as a team grows past one or two people.

How to use this map

Move top to bottom through the web tiers first (00–07), then quality/tooling (08–09), then branch into React Native once React itself feels natural — the mobile tier assumes you already know the component model.

On the SaaS-specific tiers

Tiers 09 onward (billing, analytics, SEO) rarely appear in generic "learn React" courses, but they're exactly what separates a portfolio project from a shippable product.
